# Part 11: 他LLMへの応用

> [!NOTE]
> 本 Part は全体の到達点である。
> Part 1〜10 では Claude Code を代表例として、制約と対策の対応を確認した。
> ここでは代表例から離れ、何が製品に依存しないかを取り出す。

## なぜこのパートがあるのか

Claude Code の設定手順を他製品へ移植することが目的ではない。移植できるのは手順ではなく、原則である。

Cursor や Cline、あるいは素のプロンプト設計でも、同じ構造的制約は現れる。同じ考え方で対処できる。同じファイル名や同じコマンドが揃っているとは限らない。

本 Part で取り出すのは、次の区別である。

- **製品に依存しないもの**: 制約の機序と、対処の考え方
- **代表例に属するもの**: CLAUDE.md や `/compact` など、Claude Code における具体策

## 製品に依存しない原則

1. **常駐の指示は短く保つ** — 同時に効いている指示が多いほど、遵守率は落ちる
2. **必要なときだけ読む** — 使わないルールを常時載せない
3. **生成と検証を分ける** — 同じ会話で作って追認させない
4. **機械的な検証はモデルの外に置く** — テスト、lint、CI は追従しない
5. **会話は短く区切る** — 履歴の膨張は品質を落とす
6. **変動させたくない軸は明示する** — 指定しない軸は事前分布で埋まる
7. **外部の一次情報に接地する** — モデルの内部知識だけに頼らない

詳細な機序は Part 1、代表例の具体策は Part 3〜10、用語の対応は [用語集](../appendix/glossary.md) を参照する。
